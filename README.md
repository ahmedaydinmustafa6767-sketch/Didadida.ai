### What You’ll Learn

This guide explains how to:

1. Create a DIDADIDA account.
2. Check your free trial balance.
3. Create an API key.
4. Prepare your first API request.
5. Review usage and remaining credits.

### 1. Create Your Account

### 2. Check Your Balance

Open **Dashboard** and look for **Current Balance**.

```text
Current Balance

```

The dashboard provides access to these sections:

| Section | Purpose |
| --- | --- |
| Dashboard | View your balance and usage overview |
| API Keys | Manage your API keys |
| Usage Logs | Review API request records |
| Wallet | Access balance and top-up information |

### 3. Create an API Key

Open **API Keys** and follow the on-screen instructions to create a key.

Store the key securely. Your application uses it to authenticate API requests.

> **Keep your API key private.**
> Do not commit it to GitHub, put it in browser-side code, or expose it in screenshots. Use environment variables or your hosting platform’s secret manager.

### 4. Prepare Your First Request

Before sending a request, obtain the following details from the platform’s API documentation:

| Required value | What it means |
| --- | --- |
| API Key | The key created in your account |
| API Base URL | The API address used by your application |
| Model ID | The exact identifier of the model you want to use |
| Request format | The endpoint and parameters supported by that model |

Use the documented API address, not the website homepage URL.

For your first test:

1. Choose an available model.
2. Follow its documented request example.
3. Send a short prompt, such as:
   ```text
   Explain what an API is in one sentence.
   ```
4. Use a small output limit if the model supports one.
5. Run the request and check the response.

A successful response confirms that your account, API key, and request configuration are working together.

### 5. Review Your Usage

After your first request:

1. Open **Usage Logs** to review the request record.
2. Return to **Dashboard** to check usage and remaining balance.
3. Review the selected model’s pricing before making larger requests.

The number of requests covered by your credits varies by model, input size, and output length. A $10 balance does not represent a fixed number of requests.

### Troubleshooting

| Issue | What to check |
| --- | --- |
| Authentication failed | Make sure your API key is complete, valid, and configured correctly |
| Model not found | Check the exact Model ID against the platform’s model list |
| Endpoint not found | Verify the API Base URL and request endpoint |
| Unsupported parameter | Check the selected model’s documented parameters |
| Insufficient balance | Review your remaining balance in the dashboard |

When asking for help, include the error message and relevant configuration, but remove your API key and any private data.
